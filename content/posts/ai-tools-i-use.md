工具清单这种东西很容易写成广告。所以我给自己定了个规矩：**只用超过三个月、且每周至少打开三次的，才能进这份清单。**

## 留在清单里的

### 对话与思考

用来做三件事：解释看不懂的概念、帮我把模糊的想法问清楚、当我写完之后充当挑刺的人。

最后一项最有价值。我的用法是把自己的草稿丢进去，配一句固定指令：

> 假设你不同意我的结论，指出三个最弱的论证，并说明它们为什么弱。

### 代码辅助

写代码时的主要用途不是「帮我写」，而是：读陌生的库、把一次性脚本改得更规范、以及解释报错。至于核心逻辑，我还是自己写——出错时我才知道该往哪儿找。

### 语音转文字

这是我今年最满意的改变。走路和通勤时的想法直接口述，转成文字再整理。它解决的是「想得到但懒得写」这个最大的瓶颈。

## 被我删掉的

- **各种 All-in-one 工作台**：功能太多，每次打开都要重新决定「现在该用哪个功能」，决策成本高于收益。
- **自动抓取一切的工具**：抓回来的信息我没时间读，只是把焦虑从浏览器搬到了另一个 App。
- **需要我维护 Prompt 库的插件**：维护成本很快就超过了它节省的时间。

## 一个配置文件

我把常用指令固化成了一个文件，避免每次重新描述：

```json
{
  "review": "指出这篇草稿里最弱的三个论证，不要夸奖，不要总结",
  "explain": "用初中生能懂的语言解释，先给结论再给原因，必要时举例",
  "summarize": "压缩到三句话，保留具体数字和结论，去掉形容词",
  "outline": "先问我三个问题以澄清目标，再给大纲"
}
```

## 我的判断标准

选工具时我只问一个问题：

> 它会让我**更多地思考**，还是更少地思考？

让我少思考的工具，无论多聪明，我都会尽快删掉。
